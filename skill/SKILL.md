# きょうのボード — 今日のタスク管制盤

今日のタスクを1枚のHTMLボードにまとめて発行する。ユーザーはそれを別ウィンドウ／サブモニタに
常時表示し、Claudeがタスクの進捗に応じて同じボードを更新する（ページ側は5分ごとに自動リロード）。

## 表示モード（最初に確認）

`~/.claude/today-board/config.json` を読む（Windows は `C:\Users\<user>\.claude\today-board\config.json`）。
形式: `{"mode": "local" | "artifact"}`

- **config がある** → その mode を使う
- **config がない（初回）** → ユーザーに次のトレードオフを示して選んでもらい、config.json に保存する（update モード 9 のためだけには聞かず、同項の今日のボードが無いときの扱いに従う）:
  - **local（ローカルファイル・PC常時表示向け）**: 固定パスのHTMLファイルをブラウザで開く方式。
    複数セッション・複数プロジェクトの情報を1枚に統合できる。ウィンドウのサイズ・配置は自由。
    スマホ等PC外からは見えない
  - **artifact（クラウドURL・モバイル可）**: Artifact として発行し URL で見る方式。
    スマホからも見られるが、別会話からの同一URL更新に失敗すると板が分裂することがある。
    Artifact ツールが使えない環境では local にフォールバックする

**移行ガード**: `state.json` の日付が今日で、かつ `url` が入っている（＝今日は既に artifact 運用中）
場合は、config が local でも**当日は artifact モードを継続**する。切替は翌日の create から。

## 状態ファイル

`~/.claude/today-board/state.json`
形式: `{"date": "YYYY-MM-DD", "mode": "local|artifact", "file_path": "<HTMLの絶対パス>", "url": "<artifactモードのみ>"}`

- state の `date` が今日 → **update モード**（既存ボードを更新）。ただし次の2つは **create モード**:
  ①local モードで、board.html のヘッダの日付が今日でない（state と板が食い違っている）
  ②board.html の `<div class="board">` に `data-tb-rolled` があり（Deck が日付の切り替えで作った板＝下記）、
  ユーザーが今日の予定の整理・今日のタスク一覧を求めた（朝の計画）。それ以外の更新（済にする・行を足す等）は、
  `data-tb-rolled` があっても update でよい（Deck v2.3 が動いていれば、update で手書き部分を変えた時点で Deck が
  `data-tb-rolled` を外し、「引き継いだボード」の知らせは消える。外れた後の板は②に当たらないので、朝の計画も
  update になる。引き継いだ行は `data-carried-from` 付きで板に残る）
- 日付が古い・ファイルなし → **create モード**（新規発行・state を上書き）。ただし、今日より後の予定を1行足すためだけには
  create に入らない（update モード 9）
- `board_edit.py status`（下記「ボードの書き方」）が、この判定を `suggest`（朝の計画のときは `suggest_if_planning`）で、
  ①の材料を `board_date`、②の材料を `rolled` で返す
- **local モードで同梱の Deck が動いていると、日付が変わったときに Deck が今日のボードを作る**
  （Deck v2.2。元のボードを `~/.claude/today-board/history/board-<元の日付>.html` へ退避し、終わっていない行を
  引き継ぎ、`state.json` の `date` も今日にする）。そのため朝の時点で state の date が今日になっていることがある
  ——そのときは、板に `data-tb-rolled` が残っていれば上の②で create に入る（Deck v2.3 で外れた後は update）。Deck が止まっているとき・artifact モードでは切り替わらないので、
  従来どおり日付で create に入る
- **state.json は Claude が Write / Edit で書く**（`board_edit.py` は読むだけで書かない）。Deck が `date` だけを
  書き換えることがある（日付の切り替えのときと、今日のボードなのに date が今日と違うとき。local モードで `url` が無く、
  `file_path` が無いかこのボードを指す場合に限る。書き換えるときは JSON を字下げ2で書き直す〔キーの順・BOM・改行の形は保つ〕）
  ので、書く前に読み直す

## ボードの書き方

board.html は複数のセッションと同梱の Deck が同時に書くファイルである。**board.html・`history/`・`.guard/`
（いずれも `~/.claude/today-board/` の下）には、同梱のスクリプト `board_edit.py` 以外で書かない。**
Write・Edit で書こうとするとボードの保護（このスキルに入っているフック）が止める。Bash・PowerShell は止めない——そこで書いた分
（`Move-Item`・`mv`・リダイレクト・自作のスクリプトを含む）は、既定の board.html に限り、タスクの行・見出し・ヘッダの日付を変えたときと、板の形を新しく崩したとき（項目の入れ子や閉じタグの欠落・DECK マーカーの崩れ・ヘッダなどの `{{…}}` の埋め残し。ファイルを消したときを含む）に、そのツールが終わった時点でボードの保護が元に戻すか、戻さずに知らせる（下記「ボードの保護の知らせを受けたとき」）。DECK マーカーの間やヘッダの進捗・更新時刻などだけの変更は、戻しも知らせもしない。`history/`・`.guard/` に書いた分と、`--board` で指す別のボードは戻さない。どの場合も、戻ることを当てにして書かない。
**HTML を手で書く手順は無い**——`board_edit.py` が操作を受け取って HTML を機械で書き換え、書く前に出来上がりの形を検査し、
崩れる形なら書かない。読むのは自由（Read でよい）。

**呼び方**: Python は `~/.claude/today-board/.guard/python.txt` に書かれた絶対パスのもの（setup が見つけた
Python。`py.exe` のこともあり、そのときも `-3` は付けない）を使い、`<スキルのフォルダ>/scripts/board_edit.py` を呼ぶ
（`<スキルのフォルダ>` はこの SKILL.md のあるフォルダ。ふつうは `~/.claude/skills/today-board`）。`python.txt` は
前後の空白と改行を除いて読む（PowerShell では `-Encoding UTF8` を省かない。省くと日本語を含むパスが化ける）。

- PowerShell: `$py = (Get-Content -Raw -Encoding UTF8 "$env:USERPROFILE\.claude\today-board\.guard\python.txt").Trim()`
  の後に `& $py "$env:USERPROFILE\.claude\skills\today-board\scripts\board_edit.py" status`
- bash: `py="$(tr -d '\r\n' < ~/.claude/today-board/.guard/python.txt)"` の後に
  `"$py" ~/.claude/skills/today-board/scripts/board_edit.py status`
- **`python.txt` が無い・そのパスの Python が起動しない・`board_edit.py` が無いときは、ボードを書かない**（ほかの手段で
  書き換えない）。ユーザーに、ボードを更新できなかったことと、スキルを入れ直す（Windows では `setup.bat` を
  もう一度実行する）よう伝える（`setup.bat` は Claude が実行しない）
- 出力は標準出力の JSON 1つ。**`version` が 1.0 より前なら書かずに、上と同じくユーザーへ伝える**（この節の操作が無い版のため）。
  `ok: false`（終了コードが 0 以外）のとき、ボードは書かれていない。`error` の文に従い、文が「ユーザーに確かめる」
  「ユーザーに伝える」と言うときは自分の判断で先へ進めない。同じ引数のままくり返さない。
  PowerShell では出力を `ConvertFrom-Json` にかけず、そのまま表示して読む（日本語が化けることがある）。
  操作の出力の `item` は、操作する前のその行の状態である（操作した後の状態は `status` で見る）
- `status` が `suggest: null` と `errors` の `UTF8` を返したときは、板が UTF-8 として読めない。create 以外の操作は書かないので、
  `status` の出力をユーザーに見せてどうするかを確かめる（作り直すなら create モード 2 の例外と 6 の確かめを通す）。
  `mode`・`state_date`・`suggest` は `--board` で指したボードのフォルダの config.json・state.json から作るので、
  artifact モード（`--board` で別の場所を指す）では当てにせず、モードは上の「表示モード」「状態ファイル」の規則で決める
- 日本語の引数がシェルで崩れる（文字化けして板に入る・項目が見つからない）ときは、引数を JSON に書いて `--ops <ファイル>` で渡す。
  JSON は **Write ツールで** `~/.claude/today-board/ops/<任意の名前>.json` に書く（シェルを通さない）。
  形は `{"op": "add", "section": "今日中", "title": "…"}`（キーは引数の名前から `--` を除いたもの。`set-crit` の on／off は
  `"value": "on"`）。書けたら `board_edit.py` が消す。PowerShell では `--ops "$env:USERPROFILE\.claude\today-board\ops\<名前>.json"` の形で渡す
- 細かい引数・出力のキーは `board_edit.py --help` と `board_edit.py <操作> --help` を見る

| やること | 操作 |
|---|---|
| 板の状態・項目の一覧を見る（書かない） | `status` |
| 新しい日のボードを作る | `create --spec <JSON ファイル>`（create モード 5・6） |
| 行を足す | `add --section <見出し> --title … [--note …] [--chip …] [--time H:MM] [--after <項目>\|--head] [--create-section]`（正式名の見出しが無ければ `--create-section` が要る） |
| 状態チップを替える | `set-chip --item <項目> --chip done\|active\|pending\|wait\|hold\|none` |
| タイトル・補足を直す | `edit --item <項目> [--title …] [--note …]`（`--note ""` で補足を消す。PowerShell では `--note=`） |
| 重要タスクを付け外す | `set-crit --item <項目> on\|off` |
| 時刻を替える・外す | `set-time --item <項目> --time H:MM\|none` |
| 今日の予定・今日中・明日以降の間で動かす | `move --item <項目> --section <見出し> [--before <項目>\|--head]` |
| 行を消す | `remove --item <項目>`（下記の確かめ） |
| 板を `history/` の版へ戻す | `restore --from history/<ファイル名>`（下記の確かめ） |

- `<項目>` は `時刻|タイトル`（時刻の無い行は `|タイトル`）・タイトルの完全一致・`status` の `index` のどれか。
  当たらない・2件以上なら書かずに候補を返す
- チップの `wait` は「条件待ち」、`none` はチップ無し。`--chip`（spec の `chip`）を省いたときは、「明日以降」はチップ無し、
  それ以外は `pending`（未）になる
- **どの書き込みでも、ヘッダの `#upd-time` は現在時刻に、進捗 N / M とバー幅は数え直した値に自動で直る**（引数は無い）。
  完了表示（`done-item`／`strike`）も、既にある行への操作（set-chip 等）では、操作した行は済チップに合わせて整う
- `--board <パス>` で既定（`~/.claude/today-board/board.html`）以外のボードを指す（artifact モードの `file_path`）。
  `--board` は操作の名前の後ろに置く（`status --board <パス>`）

**確かめが要る操作**（`--confirmed` は、ユーザーが確かめた後にだけ付ける）:

- **`remove`**: まず `--confirmed` なしで実行する（対象を返すだけで消さない）。その行を消してよいかをユーザーに確かめてから
  `--confirmed` を付ける。**`--confirmed` のときは番号（`index`）で指定できない**——確かめた後に番号がずれうるため、
  `時刻|タイトル` かタイトルで指定する。同じタイトルで時刻の無い行が2つあるなど1行に絞れないときは、先に
  `edit --item <index> --title <ほかと重ならない仮のタイトル>` で区別してから、その仮のタイトルで `remove` の確かめと
  `--confirmed` を行う（仮のタイトルを付けることもユーザーに伝える）。edit の出力の `item`（操作する前の状態）が、区別したかった行（見出し・時刻・タイトル・補足）と合わなければ、`edit` で元のタイトルに戻し、そのことをユーザーに伝えてやり直す
- **`restore`**: 戻す版は `status` の **`restorable_today`**（`history/` の版のうち、いまの板と日付が同じで形の正しい、実際に
  戻せる版）から選ぶ（`restorable` は名前の形だけで選んだ一覧で、戻せない版を含む）。`--confirmed` なしで実行すると差
  （`only_now`＝いまの板にだけある行・`only_restore`＝戻す版にだけある行）を返すだけで戻さない。差をユーザーに見せ、
  戻してよいと言われてから `--confirmed` を付ける。戻した後、`only_now` の行をユーザーに見せ、足し直してよいと言われた行だけを
  `add` で足す。`restorable_today` が空なら書かずに、`status` の出力をユーザーに見せてどうするかを確かめる（create で作り直すこともできる＝create モード 2 の例外。どうするかはユーザーが決める）
- **`create`**: 消える行の確かめ（create モード 6）

**ボードの保護の知らせを受けたとき**（ツールの結果か、プロンプトの前に届く）:

- **止めた**（Write・Edit が拒否された）: 同じ書き込みを別の手段（Bash・PowerShell・別名のファイルからの差し替え）で試さない。
  やりたかった変更を `board_edit.py` の操作でやり直す
- **元に戻した**: 自分がボードを書き換えようとしたのなら、`status` で戻った後の板を見てから、`board_edit.py` の操作でやり直す。
  自分が書いた覚えが無いとき（ユーザーの手の編集・ほかのプログラムと思われるとき）は、戻したことと、戻す前の版の退避先
  （知らせにある `history/…-foreign-…`）をユーザーに伝える
- **知らせるだけ**（元に戻していない）: 自分の判断で戻さない。知らせの内容と退避先をユーザーに伝える。知らせが restore で
  戻せると言っていれば、`restore` を `--confirmed` なしで実行して差をユーザーに見せ、戻すと言われたときだけ `--confirmed` を付ける。
  知らせがスキルの入れ直しを求めていれば、そのままユーザーに伝える（`setup.bat` は Claude が実行しない）
- **戻せなかった**: `status` で板を確かめる。崩れていれば（`errors` がある）上の `restore` の手順でユーザーに確かめる。
  崩れていなくても、戻せなかったことと退避先をユーザーに伝える
- 知らせの文が「この出力をユーザーに伝える」と言うときは、そのとおり伝える

## create モード

1. **時刻確認**: 先に `date` コマンドで現在日時を確認する（推測しない）。
2. **タスク収集**: まず会話コンテキストから今日のタスクを拾う。会話に十分な情報が
   なければプロジェクトのログ・メモ・直近の作業記録を読む。会話だけで足りるならログ読取は省略してよい。
   **`status` の `rolled` に日付がある（Deck が前の日から引き継いだ板）ときは、そこにある行
   （`carried` 付きの引き継ぎ行・ルーチンタスク・明日以降）を必ず候補に取り込む**（落とすなら
   ユーザーに確かめる）。時刻付きの予定だった行は今日中へ移されており、元の予定時刻は board.html の
   `data-orig-time` にある（Read で見る）。create は引き継ぎの印（`data-tb-rolled`・`data-carried-from` 等）を
   書かないので、作り直した板からは引き継ぎのチップと「引き継いだボード」の知らせが消える。
   **`board_date` が今日より前の板（Deck が切り替えていない前の日の板）から作るときは、その板の「明日以降」の行も
   `status` で読んで必ず候補に取り込む**（落とすならユーザーに確かめる。前の日の板には消える行の確かめが無いので、
   spec に入れないと新しい板に残らない。元の板は `history/` に残る）。
   **今日のボードが既にある（`rolled` が無い）ときは、予定の組み直しに create を使わない**——予定の組み直しは update モードの
   1行ずつの操作（`add`・`move`・`set-chip`・`edit`・`set-time` 等）で行う。create は新しい日のボードを作るときに使う
   （`status` の `suggest` が create でも、`board_date` が今日で `rolled` が無ければ今日のボードがある）。例外は、今日の板に1行ずつの操作も
   `restore` も使えないとき（形が崩れていて `restorable_today` が空・ヘッダの日付が読めない・UTF-8 として読めない）に、ユーザーが作り直すと決めた場合だけで、
   そのときも 6 の消える行の確かめを通す。
3. **4分類に整理**（セクション名は以下を正式名とする。時間軸で分ける）:
   - **今日の予定** — 実施時刻が明確なもの（時系列順に並べる）
   - **今日中** — 時刻は決まっていないが今日やるもの。**条件成立で発火するタスクもここ**
     （「条件待ち」チップ＋補足欄に発火条件を書く。「条件」という擬似時刻表示は使わない）
   - **ルーチンタスク** — セッション締めの定型作業（ログ更新・gitチェック等）
   - **明日以降** — ユーザーの今日より後の予定。会話に出たものは頼まれていなくても拾い（足す基準は update モード 9）、
     ログ・メモにあるものを拾うかどうかは任意。最下部に置く（チップ不要・進捗に数えない）
4. **強調は基準で決める**: その日に特に重要なタスク（遅れると影響が大きいもの、ユーザーが重要と言ったものなど）にだけ
   crit を付ける（件数の上限は無い）。迷ったらユーザーに確かめる。ユーザーが「これを重要に」「これは外して」と言えば、
   そのとおりにする（`set-crit … on`／`off`）。ユーザーが言っていないのに Claude が付けたときは、理由と一緒に伝える。
5. **spec を書く**: セクションと項目を JSON にして、**Write ツールで** `~/.claude/today-board/ops/<任意の名前>.json` に書く
   （PowerShell から渡すときのパスは `"$env:USERPROFILE\.claude\today-board\ops\<名前>.json"`）:
   `{"sections": ["今日の予定", "今日中", "ルーチンタスク", "明日以降"], "items": [{"section": "今日の予定", "time": "9:00", "title": "…", "note": "…"}, {"section": "今日の予定", "time": "16:00", "title": "…", "crit": true}, {"section": "今日中", "title": "…", "chip": "wait", "note": "<発火条件>"}, {"section": "明日以降", "title": "…"}]}`
   （項目のキーは `section`・`time`・`title`・`note`・`chip`・`crit` だけ。見出しは `sections` の順に並び、そこに無い
   `section` は後ろに足される）。ヘッダの日付は `board_edit.py` が PC の今日の日付で、半角数字の
   `YYYY-MM-DD（曜）` 形式（例: `2026-08-05（水）`）に書く。board.js はこの日付で「今日のボードか」を判定し、
   今日でない板では Deck への書き込み4経路が止まる（画面には「書き込み停止中」の知らせが出る。詳細＝下記
   「テンプレの自動機能」の**発行済みボード判定**）。年なし表記（`8/5（水）`）も判定器は受理するが年を照合しないため、
   書く側だけ年ありに寄せてある——判定器を「年あり必須」へ戻す変更はしないこと。
   **CSS・JS・猫アイコンは外部ファイル**（`board.css` / `board.js` / `cat.png`）で、**読まない・書かない・編集しない**
   （デザイン変更が必要なときのみ assets 内のマスターを編集）。
6. **発行**:
   - **local モード**: `create --spec <spec のファイル>` を実行する（PowerShell では
     `--spec "$env:USERPROFILE\.claude\today-board\ops\<名前>.json"`）。create は board.html を書き、静的ファイル
     （`board.css` / `board.js` / `cat.png`）をこのスキルの `assets/` から board.html の隣へ**毎回写す**
     （中身が同じなら写さない。`~/.claude/today-board/` 側は生成物であり、ユーザーが編集する場所ではない。
     スキルを更新しても実行系に古い版が残り続けるのを防ぐ。Deck v2.3 が動いていれば、Deck も起動時と5分ごとに
     同じ向きでそろえる）。置き換える前の板は `history/board-<その板の日付>-before-create-<時刻>.html` に残る。
     **消える行の確かめ**: いまの板が今日の板か日付の読めない板で（Deck が引き継いだ板を除く）、spec に無い行があると、
     create は書かずに `ok: false` と `missing`（消える行。`no` がこの一覧の番号）を返す。そのときは missing の行を
     ユーザーに番号付きで見せ、残す行を選んでもらう（4件以下なら選択肢で、5件以上なら番号で答えてもらう）。
     残すと言われた行を spec に足して（Write で書き直して）もう一度 create を実行する。足さない行が残るときは、
     その行が消えることをユーザーが確かめてから `--confirmed` を付ける。`missing_incomplete` が true のとき
     （いまの板の形が崩れている・UTF-8 として読めない）は、missing に無い行もありうるので、board.html を Read で読んで
     ユーザーに見せる。前の日の板・Deck が引き継いだ板・板が無いときは確かめずに作る。
     パスが固定なので、ユーザーが開きっぱなしのブラウザタブは、新しい日のボードが書かれると
     自動リロードで切り替わる（日付が変わったときに新しい日のボードを書くのは、Deck が動いていれば Deck、
     止まっていれば次の create）。初回のみ既定ブラウザで開き（Windows:
     `Start-Process "$env:USERPROFILE\.claude\today-board\board.html"` ／ macOS:
     `open ~/.claude/today-board/board.html` ／ Linux: `xdg-open ~/.claude/today-board/board.html`）、
     「このウィンドウを開いたままにすれば、新しいボードが書かれるたびに自動で最新化される」と伝える。
     2日目以降は開き直し不要。
   - **artifact モード**: `create --spec <spec のファイル> --board <書く先の HTML のパス>` で HTML を作り、
     そのファイルを Artifact ツールで発行する。favicon は 📋 固定。title は「M/D(曜) きょうのボード」。
7. **state 保存**: date・mode・file_path（・url）を書く（create は state.json を書かない＝上記「状態ファイル」）。

## update モード

1. **書く前に `status` で板を読み直す**（local モードでは他のセッションと Deck が並行して書いているため。
   `board_edit.py` は書く瞬間の板に操作を当てるので、直前の Read の内容で上書きすることは起きない）。
   今日のボードがあるときの予定の組み直し（行を足す・動かす・状態を変える・文言や時刻を直す・消す）は、
   すべて1行ずつの操作で行い、create で作り直さない（create モード 2）。
2. **複数セッション・複数プロジェクト運用（local モード）**: プロジェクトごとに
   プロジェクト名の見出しでセクションを区切り（`add --section <プロジェクト名> --create-section`）、
   **自分のセッションが担当するセクションだけを追加・更新する**。他セクションの内容は変更しない。
   例外として、項目 9 の行は「明日以降」へ足す（この見出しはセッションをまたいで共有する。足すだけで、ほかのセッションの行は変えない）。
   進捗カウント（N / M 完了）とバー幅は `board_edit.py` が他のセッションの分も含めて数え直す
   （数えるのは「今日の予定」「今日中」だけ。プロジェクト名で区切ったセクションは数えない＝board.js と Deck の再計算も同じ）。
   **手書きと自動収集の役割分担**: Deck ウォッチャーを併用している場合、各セッションの作業進捗は
   自動収集（DECKマーカー間）に任せ、**手書きセクションには書かない**（Deck はセッションごとのカードを
   自動で作る〔同じプロジェクトで同じタイトルのセッションは最新の1枚に畳む〕。タスク一覧の道具〔TaskCreate 等、またはデスクトップアプリの計画一覧〕を使えば進捗も載り、
   使わなくても状態〔作業中／入力待ち等〕は載る）。手書きするのは Claude が編集価値を足すものだけ＝今日の予定・今日中
   （重要タスク・条件待ち含む）・ルーチンタスク・明日以降。同じタスクを両層に重複表示させない。
3. 変更するのは主に状態チップ（`set-chip`）。**ヘッダの更新時刻（`#upd-time`。画面上の表示名は「タスク更新」）・
   進捗カウント・バー幅は、どの操作でも `board_edit.py` が自動で直す**（チップを1つ替えただけの更新でも直る）。
   `#upd-time` は**ボードの中身がいつ書かれたかを示す唯一の情報**で、画面にはここからの経過（「N分前」）が出る。
   Deck が出す「自動収集 HH:MM」は別の時刻（セッションカードを作り直した時刻）で、ヘッダには反映されない。
   **完了状態は状態チップだけで表す**: 完了したタスクは `set-chip --chip done` にする。淡色化（`item` の `done-item`）と
   打ち消し線（`task-title` の `strike`）は board.js が済チップを見て表示時に付け外しし、正本側は `board_edit.py`
   （操作した行）と Deck が済チップに合わせて整える。完了以外（未・条件待ち・保留・進行中）も同様にチップだけを替える。
   ※同じ「完了」を3箇所（チップ・淡色化・打ち消し線）で持つと、状態変更時に一部だけ書き換わって食い違う
   （特に済→保留の差し戻しで淡色化が残り、承認待ちが完了済みに見える）。そのため事実は済チップの1つだけにしてある。
   **進捗カウントの定義**: N / M は**「今日の予定」「今日中」のチップ付き item の合算のみ**。
   「ルーチンタスク」「明日以降」と自動収集（DECKマーカー間）は数えない。
4. **飛び込み作業の計画登録**: 計画に無い作業を始めたセッションは、
   **「今日中」セクションに自分の作業を1行追加**する（`add --section 今日中 --title … --note <プロジェクト名>`、
   着手中なら `--chip active`）。これは計画への登録であり
   重複ではない（TaskCreate が使えるセッションで、実働タスクの明細を登録し `metadata.plan` に
   この計画タスク名を書くと、Deck がセッションカードに「計画: ○○」と対応表示する。
   デスクトップアプリの計画一覧〔update_plan〕には計画名の欄が無いので、この対応表示は出ない）。
5. **タスク追加時の重複判定**: 追加前に必ず `status` の項目の一覧（`title`）を読み、
   **意味で**重複を判定する。ファイル全体への文字列一致で判定しない——①注記内の言及を
   タスク行と誤認して追加を見送る ②別の言い回しの同一タスク（他セッションの自己登録行）を
   見逃して重複を作る、の両方向に壊れる。「既に在れば黙って何もしない」形にしない——
   追加すると決めたら `add` を実行する（`add` は必ず1行足し、項目数が1つ増えたことを自分で確かめる）。
   別セッションが自己登録した行がある場合はそちらが正（自分の行は追加しない）。
6. artifact モードでは同じ file_path を `--board` で指して操作し、Artifact を再発行する（state の `url` を渡して同一URL維持）。
   別セッションでファイルが消えている場合は create（`--board` に同じ file_path）で作り直し、state の `url` を渡す。
7. ユーザーへの報告は一言でよい（例:「ボード更新済み（3/9完了）」）。
8. **重要タスクの付け外し**: `set-crit` で付けるときの基準は create モード4 と同じ（件数の上限は無い。ユーザーが言っていないのに付けたときは、理由と一緒に伝える）。
9. **ユーザーの今日より後の予定の登録**: ユーザー本人が今日より後にやる予定（日付未定・「いつかやるかも」を含む）が会話の話題に出たら、頼まれていなくても
   「明日以降」に1行足す（`add --section 明日以降 --create-section --title … [--note …]`。見出しが既にあれば `--create-section` は何もしない）。
   一度に複数出たら、足す対象を1行ずつ足す。補足には、分かっていれば日付・条件を書く（複数のプロジェクトで使っているならプロジェクト名も）。
   チップは付けない（`--chip` を省く）。足す前に項目 5 の重複判定に従う（意味で同じ行があれば足さない。日付が新しく分かったなら、自分の行は `edit` で補足を直す）。
   artifact モードは項目 6 のとおり `--board` で指して再発行する。
   - **足さないもの**: ユーザーが「やらない」と言ったもの／今日やるもの（「今日の予定」か「今日中」へ）／説明のための例え話／
     Claude が提案してまだ受けていないもの／いま進めている作業の次の手順／他の人の予定／ファイルで読んだだけでユーザーが話題にしていない予定
   - **足したら、何を足したかをユーザーに一言伝える**（例:「ボードの明日以降に「○○」を足しました。不要なら消します」）。
     引き継いだ板（`status` の `rolled` に日付がある）に足したときは、「引き継いだボード」の知らせが消えることも一緒に伝える。
     消すときは「ボードの書き方」の `remove` の確かめに従う
   - **板が無い／前の日・先の日付の板のとき**（今日のボードが無いとき）は、足さず、create も走らせない。
     今日のボードが無いのでまだ足していないことをユーザーに一言伝え（1会話で1回）、同じ会話で今日のボードができたら足す（create するなら spec に入れる）。
     前の日の板には足さない（`add` は板の日付を見ずに書けてしまうが、今日のボードに載ったことにならない）。
     artifact モードでファイルが消えているときも、項目 6 の作り直しをこのためだけには行わない
   - **`status` の `errors` があるとき**（日付の読めない板・UTF-8 として読めない板・形の崩れた板など）は、足さず、create も restore も走らせない。板に問題があるのでまだ足していないことと `errors` の内容をユーザーに一言伝え（1会話で1回）、直すかどうかはユーザーに任せる（`errors` の文が求める行の提示と作り直しの確かめは、ユーザーが直すと言ったときに行う）。同じ会話で今日のボードが正しい形になったら足す

## show モード（「ボードを見せて」と言われたとき）

ユーザーが「きょうのボードを見せて」「ボードを開いて」等、**閲覧を求めたとき**の動作。
**「今日のやることを教えて」「今日のタスクは？」等、その日のタスク一覧を求められたときも、
create/update の完了後に必ず show まで実行する**（一覧の回答＝ボードを見える状態にすることまで。
チャットの文面だけで済ませない）:

1. state の `date` が今日でない場合は、先に create モードでボードを発行する。
2. **local モード**: 既定ブラウザで自動的に開く（Windows: `Start-Process` ／ macOS: `open` ／
   Linux: `xdg-open`。初回に限らず、見せてと言われたら毎回開いてよい。
   既に開いているタブがあっても固定パスなので実害はない）。あわせてチャットには
   進捗サマリ（N / M 完了と主要な未了タスク）を一言添える。
3. **artifact モード**: state の `url` を提示する。
4. show はボードの内容を変更しない（タスク状態の更新が必要なら update モードを併用する）。

## 状態チップの使い分け

| チップ表示 | `--chip` の値 | 使いどころ |
|---|---|---|
| 済 | `done` | 完了。チップだけを替える（淡色化・打ち消し線は board.js が表示時に自動で付ける） |
| 進行中 | `active` | いま着手している作業 |
| 未 | `pending` | 未着手 |
| 条件待ち | `wait` | 他タスクの結果次第で発生する条件付きタスク |
| 保留 | `hold` | ユーザー判断待ち・方針未確定 |
| 重要タスク | （`set-crit … on`） | その日に特に重要なタスク（付ける基準は create モード4。項目の `crit` と「重要タスク」のチップが付く） |

## テンプレの自動機能（手動で付けない・壊さない）

`board.js`（外部ファイル・読む必要なし）が以下を自動処理する。生成・更新時にこれらを
付けたり消したりしようとしないこと（`board_edit.py` の操作にも、これらを書く引数は無い）:

- **完了表示の自動整合** — 手書きセクションの各タスクについて、済チップがあれば淡色化
  （`done-item`）と打ち消し線（`strike`）が自動で付き、無ければ自動で外れる。
  整合は2層で走る:
  ①**board.js** が表示時に DOM へ適用する（Deck の有無に関わらず効く・正本は変わらない）
  ②**Deck** が board.html を更新するとき、正本側も同じ規則で書き直す（チップ・タスクのテキスト・
  順序・セクション所属は変えず、`class` のトークンだけを足し引きする。変更が無ければ書かない）。
  `board_edit.py` も、既にある行への操作（set-chip 等）では、操作した行だけは同じ規則で整える。
  したがって**正本に `done-item`／`strike` が付いていることがある**——それは Deck か `board_edit.py` が整えたものか、
  過去に手書きされた残骸で、いずれにせよ状態の判断には済チップだけを見る。
  自動収集カード（`data-sid`）は Deck がチップのみを出力する設計のため対象外（見た目を変えない）
- **「▶ 次」チップ + 枠ハイライト** — 予定時刻がまだ来ていない未完了の時刻付きタスクのうち、**板の上から順に見て最初のもの**に
  自動付与（時刻の早さではなく並び順で選ぶ。重要タスク〔`crit`〕の行には枠は付かない）
- **「時刻超過」チップ** — 予定時刻（その分ちょうどを含む）に達した未完了タスクに自動付与（`active` チップ付きは除外）
- **時刻トリガー到達時の通知** — **通知音の発音は Deck ウォッチャーが行う**（board.js は鳴らさない）。
  **通知音の既定は OFF**（⚙で ON にする）。ページ内再生（WebAudio）を使わないのは、ブラウザの
  自動再生制限によりページ上で一度もクリックしていない状態では鳴らず、さらに5分ごとの自動リロードで
  クリックによる解除が失効するため（サブモニタに置いて触らない使い方と両立しない）。
  したがって **Deck を起動していない／停止しているときは通知音は鳴らない**
  （監視ねこの欄に「停止」が出る。接続情報の無い板では「不明」）。ポップアップは2経路ある: ①**Deck 経路**＝Deck が「未確認通知」
  として保持し、board.js が3秒ごとに取得して描画する。**リロードしても未確認分は復元され、
  消えるのはクリックしたとき、「30秒で自動」を選んでいるときの自動消滅時、および日付が変わったときだけ**
  （保持は1日200件まで）
  （ただし発行済みボード判定が偽の板では ack が止まるため、クリックで消してもリロードで復活する）
  ②**board.js のローカル経路**＝**Deck が無い／停止中でもポップアップは出る**が、
  localStorage の発火済み記録により**リロード後は復元されない**。ポップアップの ON/OFF・消え方・
  通知音の ON/OFF・音種は⚙設定パネルでユーザーが切り替える（Claude は関与しない。ポップアップの ON/OFF と消え方は
  localStorage 保存でブラウザ内だけ。通知音の ON/OFF と音種は Deck だけが持つ＝`sound.json`。board.js は読み込み時に
  読んで表示するだけで、送るのは⚙を操作したときだけ。Deck が応答しないときは操作できず、⚙に知らせが出る）
- **Deck（監視ねこ）の生死表示** — Deck を使っている場合、board.js が「監視ねこ」セクションに
  Deck の状態の行を注入する。Deck は自分の停止を board.html に書けない（書き手が Deck 自身のため）ので、
  3秒ごとの通信の結果から判定してブラウザ側で描画する。出し分けは「稼働」（このボードの Deck が応答）・
  「停止」（応答が無い）・「不明」（ボードの DECK マーカーの間に接続情報が無い＝Deck が止まっているか、受信ポートを取れずに
  動いているか、マーカーが欠けている〔片方だけ・順序が逆を含む〕。または応答が Deck のものと確かめられない）・「写し」（Deck は動いているが、このページは
  Deck が見ている board.html ではない）・「古い」（接続情報が古い。Deck を再起動した直後なら読み直しで戻る。
  同じトークンのまま2回読み直しても変わらなければ、Deck の再起動に合わせた読み直しは止める（5分ごとの再読み込みは続く）。今日のボードでない板では、Deck の再起動に合わせた読み直しはしない）。**HTML 正本に書かない**（書くと二重に出る）。
  なお監視ねこセクションは Deck が DECK マーカー間に出力するため、**Deck が一度も走らないまま
  発行された板では、このセクションごと存在せず生死行も描かれない**。
  「停止」（または「不明」のうち Deck が止まっている場合）を見て Claude が Deck を起動し直すときは、`Start-Process` で `pythonw` を直接起動したり `start-deck.bat` を実行したりせず、スタートアップのショートカット `today-board-deck.lnk` を `explorer.exe` で開く（直接起動した Deck は起動したプログラムの子孫になり、そのプログラムと一緒に止まりうる）。起動と確かめは同じコマンドで行い、そのコードは Deck の README（`~/.claude/today-board/deck/README.md`）の「ほかのプログラムから起動するとき（Claude Code など）」にある。この節は 2026-10-28 に足したもので、それより前に `setup.bat` で配置した README には無い（Deck の版の表記が同じでも無いことがある）。節が無いときも起動はショートカットを `explorer.exe` で開く形で行い、ユーザーには「切り離しは未確認」と伝える。ショートカットが無いときは起動せず（ショートカットを作らず、`setup.bat` も実行せず）、その旨をユーザーに伝える
- **発行済みボード判定（Deck への書き込みガード）** — board.js は読み込みのたびに一度だけ
  「この板は今日発行されたものか」を判定する（①ヘッダ等の主要位置に未置換プレースホルダが
  無い ②ヘッダの日付が今日）。偽のとき（発行前のテンプレ・過去日の板・日をまたいで開いた
  ままの板・日付が読めない表記）は、Deck への**書き込み4経路だけ**が止まる——通知音の設定・
  時刻上書きの中継・通知の確認（ack）・D&D 移動の HTML 正本への反映。読み取り（Deck の
  生死判定・⚙の通知音の表示）は従来どおり動くが、⚙の通知音は操作できず、⚙にその知らせが出る。偽のときは、ヘッダの下に「書き込み停止中」の知らせが出て、
  タブの題の頭に ⚠ が付く（下記「今日でないボードの知らせ」。細かい理由はブラウザのコンソールにも出る）。
  なお、別の場所へ写したボードは、この判定とは別に、Deck が断る理由から監視ねこの行に「写し」と出る
  （Deck を再起動した後の写しは、トークンが古くなるので「古い」と出る＝上の生死表示）。
  **本節の各項目にある「Deck 稼働中／Deck が無い・停止中」という条件は、いずれもこの判定が
  真であることを前提とする**——Deck が動いていても、今日の板でなければ同じく止まる。
  日付の書式は create モード 5 を参照。
- **今日でないボードの知らせ** — 発行済みボード判定が偽の板では、ヘッダの下（`.updated` の直後）に
  `#tb-board-notice`（`role="status"`）を board.js が入れ、見出し語「書き込み停止中」と、何が止まっているか・
  どうすれば直るか（多くは「Claude に「今日のボードを作って」と頼む」）を出す。文面は、過去の日付
  （Deck の稼働／停止・接続情報なし／写し／通信の不調で分ける）・先の日付・読めない日付・発行前のテンプレート・
  artifact（`file:` 以外で開いたページ）で出し分ける。Deck が動いている過去日の板では、Deck が今日の板を
  作るのを待つため、読み込みから90秒は出さずに60秒の時点で1回だけ読み直す（その日のその板の組み合わせごとに
  1回）。また、どの板でも日付が変わった直後（0:00 から20秒後）に1回読み直す。**HTML 正本に書かない**
- **日付の切り替え（Deck v2.2）** — local モードで Deck が動いていると、ヘッダの日付が今日より前になった
  ボードを Deck が今日のボードに作り替える（PC のローカル時刻の暦日で判定）。元のボードは
  `~/.claude/today-board/history/board-<元の日付>.html` へ退避し（同名があれば `-2` 等。自動では消さない）、
  終わっていない行を引き継ぐ: 今日の予定の済は捨て、時刻付きの未完了は今日中の先頭へ移す（時刻の欄を外し、
  元の時刻は `data-orig-time` に残す）／今日中とプロジェクト名のセクションは済を捨てて残りを引き継ぐ
  （空になったプロジェクト名の見出しは除く）／ルーチンタスクは全部残して済を未に戻す／明日以降はそのまま。
  引き継いだ行には `data-carried-from="<元の日付>"`、`<div class="board">` には `data-tb-rolled="<元の日付>"` と
  `data-tb-rolled-fp`（切り替えたときの手書き部分の指紋）が付き、
  board.js が「引き継いだボード」の知らせと、行ごとのチップ（例「↪ 10/26 9:00 の予定から」。時刻が無ければ「↪ 10/26から」）を出す。
  ヘッダの日付・`<title>`・`#upd-time`・進捗は今日の値になり、`state.json` の `date` も今日になる。
  対象外＝artifact モード（config の mode が artifact、または state に `url` がある）・state の `file_path` が
  別のボード・DECK マーカーが1組でない板・構造が崩れた板・今日の予定の時刻付きの未完了の項目に、時刻の要素がちょうど1つでないものがある板・日付が読めない／先の板（いずれも何もしない）。
  **これらの属性は `board_edit.py` の操作では書かない**（create で作り直すと消える＝create モード 2）。
  Deck v2.3 は、切り替えの後に Deck 以外の書き手が手書き部分（ヘッダの日付と、DECK マーカーの外のセクション見出しと
  項目）を変えた時点で `data-tb-rolled` を外す（「引き継いだボード」の知らせが消える）。切り替えたときの手書き部分の
  指紋を `<div class="board">` の `data-tb-rolled-fp` に持たせて比べるので、Deck が止まっている間に変えた板も、
  Deck が起動したときに外れる。誰も触らなければ知らせは出たまま。行ごとの `data-carried-from`・`data-orig-time` とチップは外さず、その行が済になって次の切り替えで
  除かれるか、create で書き直されるまで残る。重ねて切り替えたときは、`data-tb-rolled` は新しい元の日付になり、
  行の `data-carried-from` は最初の値を保つ
- **ボードの点検** — 読み込み時に board.js が次のものを見つけたら、見出し語「ボードの点検」の知らせ
  （`#tb-board-check`）を出す: ①項目の入れ子（閉じタグの欠落で後ろの項目が前の項目の中に入った形）
  ②DECK マーカーの欠落（2つのうち片方でも無いとき。ボードを `file:` で開いたとき〔local モード〕だけ見る）
  ③正式名に似ているのに正式名でないセクション見出し。拾うのは、正式名の語と組み合わさった形で、見出しの全体が
  それだけのもの（後ろに括弧書きが付くのは可）に限る: 「本日」「きょう」「今日」＋（「の」）＋「予定」「中」「タスク」
  「やること」（例「本日中」「今日のタスク」）／「明日」「あした」だけ、またはそれに「の予定」「以降」「から」が付いたもの
  （例「明日」「あしたから」）／「ルーチン」「ルーティン」だけ、またはそれに「タスク」「ワーク」が付いたもの
  （例「ルーティン」）。正式名そのもの（今日の予定・今日中・ルーチンタスク・明日以降で始まるもの）は除く。
  プロジェクト名の見出しは、この形でない限り対象外（「きょうのボード」「今日の記録ツール」「明日香アプリ」
  「ルーチン化ツール」は拾わない）
  ④Deck v2.4 が形の崩れに気づいて崩れる前の版を `history/` へ退避したこと（DECK 領域の `#deck-lastgood`）。
  また、時刻の欄が `H:MM` として読めない未完了の項目には「時刻を読めない」チップを付ける（読めない時刻では
  通知音・ポップアップ・時刻超過が発火しないため）。中身は直さない。**HTML 正本に書かない**。
  知らせの末尾は「Claude に「ボードを直して」と頼んでください。」——そう頼まれたら、`board_edit.py` で、知らせに出た点だけを直す
  （自分のセクションの外に当たる場合も、この直しに限って触れてよい。直したセクションと箇所はユーザーに伝える）:
  ①②④は、崩れた板には `board_edit.py` の行の操作が書かないので、`restore` で崩れる前の版へ丸ごと戻す——`status` の
  `restorable_today` から版を選び、「ボードの書き方」の `restore` の確かめの手順で戻し、欠けた行は `add` で足し直す
  （`restorable_today` が空なら書かずに、`status` の出力をユーザーに見せてどうするかを確かめる）
  ③は正式名に直してよいかをユーザーに聞く。見出しの名前を変える操作は無く、`move` も正式名でない見出しの項目は動かせないので、直してよいと言われたら、
  その見出しの項目を1つずつ、`status` の時刻・チップ・補足を写して `add` で正式名の見出しへ足し直し（正式名の見出しが無ければ `--create-section` が要る。重要タスクだった項目は `set-crit … on` で付け直す）、
  元の行を `remove` で消す〔「ボードの書き方」の確かめの手順〕。
  残った見出しは消せないので、そのことをユーザーに伝える。
  タスクの文言・状態は、ユーザーに確かめずに変えない
- **テーマ切替（自動/ライト/ダーク）・強調色の変更** — 同じく設定パネル（localStorage）
- **時刻の手動変更（✎印）** — ユーザーがボード上で時刻をクリックして変更できる。
  これは**ブラウザ内のみの変更で、HTML正本には反映されない**。ただし**上書きは Deck へ中継され、
  通知（音・ポップアップ）は新しい時刻で出る**（Deck 稼働中で、かつ上記の発行済みボード判定が
  真の板に限る）。ユーザーが「時刻を変えた」と
  チャットで伝えてきたら、`set-time` で HTML側の時刻も合わせて記録を一致させる
  （ヘッダの `#upd-time` は同じ書き込みで自動で直る）
- **更新時刻からの経過表示・手動リロードボタン** — ヘッダの `#upd-time`（`board_edit.py` が書いた HH:MM）
  だけを基準に「N分前」を出す（120分以上は「約N時間前」）。**Deck の「自動収集 HH:MM」とは
  一本化しない**——意味の違う2つの時刻で、混ぜるとボードの中身の鮮度が読めなくなるため
  （自動収集はセッションに動きがあるたびに数秒以内で作り直されるので、混ぜるとほぼ常に「たった今」になる）。数分程度の未来の時刻は
  「たった今」に倒す。それ以上先の時刻は、**ヘッダの日付が今日のボードに限り**経過分を作らず
  「更新時刻が未来」と出る——前日のボードを開いたまま日をまたいだ場合は日跨ぎとみなして
  経過が出る（前日 23:50 に書いたボードを当日 0:10 に見れば「20分前」）。
  ヘッダは `board_edit.py` が書くたびに現在時刻へ直す（update モード 3）
- **日付ホバーのカレンダーポップアップ** — ヘッダ右上の日付にホバーで当月カレンダー表示（◀▶で月移動）
- **計画紐づけチップ** — 自動収集カードの補足行末尾「／計画: ○○」を輪郭付きチップに変換して表示
  （Deck の出力形式はそのまま・表示だけ board.js が加工。HTML側で手動でチップ化しない。Deck がこの形を出すのは TaskCreate の `metadata.plan` を持つカードだけ。なお board.js は手書きの item の補足欄にある「／計画:」も同じくチップにする）
- **タスクのD&D移動** — ユーザーが「今日の予定/今日中/明日以降」の3セクション間でタスクを
  ドラッグ移動できる（ルーチンタスク・全セッションは対象外）。**Deck 常駐中は移動が HTML 正本へ
  自動反映される**（反映できたときは、チャットでの連絡は不要で、Claude はファイルを読むだけで移動後の状態を見る）。
  Deck が無い／停止中のとき、上記の発行済みボード判定が偽の板、および Deck が反映できずに失敗を返したとき
  （403・409・500・503 等）か 1.5 秒以内に答えなかったときは localStorage 保存の
  ブラウザ内変更にフォールバックする（失敗を返したときと答えなかったときは、画面の右下に「移動を保存できませんでした。…」の
  知らせが出る。Deck 側の記録は `watcher.log` の「移動受信: … → 409」等の行）——その場合に
  ユーザーが「○○を動かした」と伝えてきたら `move` で HTML側にも同じ移動を反映して一致させる
  （進捗カウントとヘッダ `#upd-time` は同じ書き込みで自動で直る）
- **セクション表示順の変更** — ⚙設定パネルの「セクション表示順」（↑↓ボタン）。これも
  ブラウザ内のみの表示設定。**HTML正本のセクション順は従来の正式順のまま変えない**
- **済タスクを隠す** — ⚙設定パネルの「済タスクを隠す」（**既定は OFF**）。これもブラウザ内のみの
  表示設定で、**HTML正本には反映されない**（済チップも `done-item` も正本にはそのまま残る）。
  対象は**手書きセクションの済タスクだけ**で、自動収集カード（`data-sid`）は含まない
  （自動収集カードには一括トグルが無く、**カードごとの ×** と「すべて再表示」で操作する）。
  **進捗カウント（N / M）とバーは隠しても変わらない**——進捗は事実であって表示設定ではないため
- **済タスクを1件ずつ隠す（×）** — 手書きセクションの**済タスク**にだけ出る × ボタン
  （出る条件は「手書きである〔自動収集カード `data-sid` でも、board.js が入れる行でもない〕・
  済チップが付いている・タスク名がある」。自動収集カードと監視ねこの行には出ない）。
  押したタスクが画面から消える。**記録の鍵は「HTML の時刻｜タスク名」**なので、
  **同じ時刻・同じタスク名の済タスクが板に複数あると、その全部が同時に消える**。
  **ブラウザ内のみ**で、**HTML正本には反映されない**（済チップも `done-item` も
  正本にはそのまま残る）。Deck へも何も送らないので、Deck の稼働／停止や
  発行済みボード判定の真偽に関係なく同じに効く。
  **進捗カウント（N / M）とバーは隠しても変わらない**（一括トグルと同じ理由）
  - **効くのはそのボードの日付の間だけ**——記録はヘッダの日付ごとに分けてあるので、
    **翌日のボードを発行するとヘッダの日付が変わり、隠したものは自動で戻る**
    （前日のボードを開いたまま日をまたいだ場合は、新しいボードを発行するまで隠れたまま）
  - **戻る経路は「⚙から戻す」か「その行が × の対象でなくなる」かの2系統**
    （日付が変わる場合は上記のとおり別扱い）。
    ①⚙設定パネルの「× で隠した済タスク」の「すべて戻す」
    ②**その行の済チップが外れること**——済でなくなった行は対象から外れて画面に戻る
    ③**その行のタスク名か、HTML 正本の時刻を書き換えること**——鍵が変わって別の行として
    扱われるため、隠れていた行が画面に戻る。**②③はどちらも Claude の update が引き金になる**
    （済→保留・進行中への差し戻し／タイトルの書き直し／時刻の書き換え）。
    なお**✎ のブラウザ内の時刻変更は鍵を変えない**ので隠れたままになる
    （鍵は元の時刻＝`data-orig` で持つため）
  - **記録（鍵）が消えるのは「その鍵を持つ済タスクが板に1つも無くなったとき」と、⚙の「すべて戻す」を押したときだけ**である。
    同じ鍵の済タスクがもう1つ残っている板では、片方を差し戻しても記録は残り、
    **同じ日に再び済にすると × を押し直さなくても隠れる**。鍵が一意な通常の板では
    記録も一緒に消え、再び済にしても × を押し直すまでは隠れない
  - つまり **Claude が update で済→保留・進行中などへ差し戻すと、ユーザーが × で隠した行は
    画面に戻る**。戻したくないという要望が出たら、それは表示設定では解決できないと伝える
  - ユーザーが「○○を消した」と言っても、**それだけを根拠に正本からその行を削除しない**
    ——消えているのは画面だけである。「片付けた」「非表示にした」「ボードから消えている」等の
    言い換えも同じ扱いで、**表示から消しただけなのか、正本からの削除を頼んでいるのかを
    確かめてから書く**。削除の依頼だったときは `remove` で消す（進捗カウント・バー幅・ヘッダ `#upd-time` は自動で直る）
- **見えるタスクが無くなったセクションの要約行** — 一括トグルと × の**どちらで隠した場合でも**、
  そのセクションに見えるタスクが1つも無くなったときは、見出しの下に「済 N件を非表示中」の
  1行が出る（**トグルが OFF で × だけの場合も出る**）。**N は「そのセクションで現に隠れて
  いるタスクの数」**——トグルと × のどちらで隠れたかを問わず1つのタスクを1回だけ数える。
  **足し算ではない**（× の対象は必ず「手書きの済タスク」なので、トグルが ON の間は
  トグル側にも含まれる＝両方に当たっても1件）。⚙の「済タスクを隠す（非表示中 N件）」とは
  **別物**で、あちらは**ボード全体**でトグルが隠している数、こちらは**そのセクション**の数。
  これも表示のみで、**HTML正本に書かない**。自動収集カードだけが消えたセクション
  （全セッション）には出ない
- **`<!-- DECK:AUTO:START -->` 〜 `<!-- DECK:AUTO:END -->` マーカー間** — 同梱の
  Deck ウォッチャー（`~/.claude/today-board/deck/`・セットアップで常駐）が全セッションの
  カード（状態と、タスク一覧があれば進捗）を書き込む予約領域。
  **マーカーも中身も編集しない**（`board_edit.py` の操作も触らない。create は、いまの板にマーカーが1組あれば
  その間をそのまま引き継ぐ）。Deck が停止している環境ではただの無害なコメントとして残る。
  マーカーが2つとも無い板では、Deck v2.5 がマーカーを足し直す——上の「ボードの点検」の②の項目のうち、Deck が書いた部分
  （「監視ねこ」「全セッション」の見出し・`data-sid` の付いたカード・`id="deck-key"` と `id="deck-lastgood"` の span 等）が、空行だけを挟んでひと続きに
  残っていればその前後に足して囲み、残っていなければ `<footer>` が1つだけのときにその直前に足す（片方だけある板・順序が逆の板・Deck が書いた部分の間に
  別の行がある板・Deck が書いた部分が無く `<footer>` が無い／複数の板は直さない。直さなかった板は「ボードの点検」の知らせが出たままになる。
  v2.2〜v2.4 の Deck は、Deck が書いた部分が残っていても囲まず、`<footer>` が1つだけなら `<footer>` の直前に空の1組を足す）。
  ヘッダの進捗カウント（N / M）には自動収集分を**含めない**（Claude が書いたタスクだけを数える）

## 注意

- **完了判定を先回りしない**。ユーザーの報告か、自分が実際に完了させた作業だけを「済」にする。
  予定時刻が過ぎただけのタスクを勝手に済にしない。
- **ユーザーの承認・判断が後続に残る作業は、承認を独立したタスク行（保留チップ）として掲示する**。
  作業行の補足欄に「承認待ち」と書くだけでは、済チップだけ見たとき全て終わったように
  読めてしまうため。作業=済、承認=保留の2行に分ける。
- **タスク行は「何を完了させるか」が分かる実行単位で書く**。決定事項・状態の見出し
  （例:「◯◯確定=△△」）をタスクタイトルにしない——完了条件が定義できない行は進捗管理できない。
  状態・経緯は task-note か会話で伝え、タイトルは動詞で終える（「〜を実施する」「〜を確認する」）。
- **他のセッションの作業状態は実物を確認してから書く**。自分の見積もり（「2〜4日想定だから
  進行中」等）で書かない。Deck 自動収集欄のセッションカードや成果物・ログを見て、
  済/進行中を実績で判定する。（セッションカードの「済」は、その会話のタスク一覧（TaskCreate 系か
  計画一覧）が全完了したこと、または計画一覧・活動のカードで完了報告が出たことを、「進行中」は
  in_progress のタスクがあるか、ターンの途中で最後の動きから 15 分以内であることを示すだけで、
  計画タスクそのものの完了・着手とは別物である。カードだけを見て計画タスクを済にしない）
- ボードは**要約であって記録ではない**。正式な記録（プロジェクトのログや課題管理）の代替にしない。
  ボード更新はログ更新の免除にならない。
- タスクの補足（task-note）は1行に収める。判断材料の詳細は会話で伝え、ボードには
  「何を・いつ・何で判断するか」だけを残す。
- artifact モードで Artifact ツールが使えない環境では、local モードにフォールバックする。
